# ERCO 多能源与碳因子预测：训练流程设计

文档用途：约定第一版样本、训练和评估接口；不是已经实现的功能，也不是实验结果。

日期：2026-09-11。状态：待用户确认书面设计；训练代码尚未新增。

## 1. 已有基础与本轮范围

- 现有 `build_erco_2023_observations.py` 负责核算和导出观测表，不承担训练职责，保持不变。
- 用户已回传云端成功记录：ERCO 2023、OGE v0.8.0、8760 小时、41 列；时间戳为 UTC 小时起点。
- 输入文件为 `data/processed/erco_2023_v1/observations.csv`，数据根目录由命令行传入，不硬编码 Windows 路径。
- 本轮实现目标是可检查的数据集构造、基础预测器与完整训练评估流程，不复现某一论文，也不承诺优于已有模型。
- 不启动云端训练，不修改原始 CSV，不将数据、模型或运行日志提交到 Git。

## 2. 实现方式比较

| 方式 | 优点 | 代价与边界 |
|---|---|---|
| NumPy/pandas 数据模块 + PyTorch 训练模块（推荐） | 数据检查可独立运行；模型、训练流程可以分别替换 | 训练时需要单独安装 PyTorch |
| 继续使用 TensorFlow/TiDE 工程 | 可复用此前 TiDE 的模型实现方式 | 新服务器尚未恢复该环境；需适配 TiDE 的数据和评估接口 |
| 仅 NumPy/pandas 的数据与朴素基线 | 直接使用现有数据环境即可运行 | 不能覆盖本轮要求的神经网络反向传播与模型保存流程 |

第一版拟采用第一种方式。朴素基线不依赖 PyTorch；训练入口延迟导入 PyTorch，避免数据准备被训练依赖阻塞。

## 3. 预测任务与字段

这是离线区域电网预测试验，不是园区实测验证，也不是实时可部署性验证。

默认配置：历史长度 168 小时、预测长度 24 小时、预测起点步长 1 小时。历史长度和预测长度可配置，不写死到网络中。

### 历史输入：11 个变量

1. `demand_mw`。
2. 九个 `generation_<fuel>_mwh` 字段，能源顺序固定为：`biomass`、`coal`、`hydro`、`natural_gas`、`nuclear`、`other`、`petroleum`、`solar`、`wind`。
3. `factor_generated_kg_per_mwh`。

### 预测输出：10 个变量

九类能源的净发电量，以及综合发电侧 CO₂ 碳因子。默认不把用电负荷列为预测目标。

- 第一版不预测九个单能源因子，也不预测分能源排放量；这些原始观测仍保留，后续扩展必须另行明确目标和损失。
- 单能源因子在非正净发电量时未定义，不能通过整表填零或整行删除来消除这些空值。
- 不使用官方参考因子、未来实际发电量、未来实际排放量或未来质量标记作为已知输入。
- 综合碳因子与分能源电量采用直接多输出预测，暂不施加物理一致性约束；综合因子不能唯一反推出各能源排放量。

默认张量形状为：`X = [batch, 168, 11]`，`y = [batch, 24, 10]`。

## 4. 时间划分与信息边界

默认边界使用明确的 UTC 时刻，不把它称为当地自然月划分：

| 集合 | 目标时间范围，左闭右开 |
|---|---|
| 训练 | 数据起点至 `2023-09-01T00:00:00Z` |
| 验证 | `2023-09-01T00:00:00Z` 至 `2023-11-01T00:00:00Z` |
| 测试 | `2023-11-01T00:00:00Z` 至数据终点之后一小时 |

这些边界应存入配置，运行时写入记录。当前数据末小时为 `2024-01-01T05:00:00Z`，不能因为日期跨到 2024 年就自动删除末尾记录。

设 `j` 为第一个待预测小时的行号：输入取 `[j-L, j)`，目标取 `[j, j+H)`。预测在 `j` 时刻发布，离线试验假设截至 `j-1` 的小时观测已可用；OGE 的实际发布延迟不满足这一假设的可能性必须持续披露。

- 一个样本的全部目标时间必须在同一集合，禁止目标窗口跨训练/验证/测试边界。
- 验证、测试窗口可以使用前一集合末尾的已发生历史作为输入，不为保持形式隔离而丢掉可用历史。
- 评估采用逐小时滚动起点：下一起点可以看到此时已经发生的观测，但不能看到它自己的未来。模型权重在评估期间不更新。
- 同一小时可能以不同预测步长多次被评估；指标按“预测起点×预测步长”计数，并额外输出每个预测步长的结果，不冒充独立样本检验。
- 输入和目标的标准化均只拟合训练时段的行；常数列的缩放因子置为 1 并记录。验证、测试不重新拟合。
- 行序、小时连续性、重复时间戳、所需字段中的 NaN/Inf、空集合和不足历史长度均应显式报错。
- 仅检查选入的输入/目标字段；其他单能源因子的预期空值不应使整个数据准备失败。
- 负净发电量保持原值，不自动裁剪；第一版模型预测也不静默裁剪，非物理解另行记录和分析。

## 5. 基线与训练流程

### 不需要训练的基线

- `persistence`：每个目标沿用预测起点前最后一个小时的值，覆盖全部预测步长。
- `seasonal24`：重复预测起点前最近 24 小时的目标序列。这里是固定 24 小时滞后，不声明与夏令时切换日的当地钟表时刻严格一致。
- `seasonal24` 要求至少 24 小时历史；预测长度超过 24 时只循环使用已知的最近 24 小时，禁止读取未来真实值。

### 用于验证训练流程的 MLP

- 模型输入为展平的历史窗口；两层隐藏层，每层宽度 128，ReLU 激活；输出 reshape 为 `[batch, H, K]`。
- 这只是可训练的流程基线，不称为 TiDE 复现或创新模型。
- 默认训练参数：Adam、学习率 0.001、batch size 64、最多 20 轮、早停 patience 5、seed 42、`num_workers=0`。
- 训练损失为标准化目标空间的 MSE。验证损失按全部样本/步长/目标累计后求均值，不能对不等大小的批次简单等权平均。
- 每轮只运行训练和验证；根据验证损失保存最佳模型。测试集不参与早停、超参数选择或每轮比较。
- 测试评估是显式入口，只读取选定的最佳模型和已保存的训练集标准化参数。
- 支持 CPU 与 CUDA；显式指定 CUDA 而不可用时清晰报错，不悄悄改用 CPU。
- NaN/Inf 损失立即失败并保留错误记录；不自动重试或改参数。

## 6. 结果、保存与可复现性

- 原单位下分别输出每个目标的 MAE、RMSE，并输出逐预测步长指标。
- 不将 MWh 与 kg CO₂/MWh 的原始误差直接平均为一个总分；不以 MAPE 作为含零发电序列的首要指标。
- 所有比较方法使用相同的有效预测起点、预测长度、目标顺序与数据划分。
- 保存输入文件 SHA256、实际生效配置、字段顺序、各集合时间范围/样本数、标准化参数、随机种子、运行环境、Git 提交号及工作区是否有改动。
- 保存 MLP 最佳参数、优化器状态、最佳轮次、逐轮训练与验证损失；支持加载最佳模型复评，不承诺第一版可无缝恢复中断训练。
- 测试结果单独保存；预测明细包含预测起点、目标时刻、预测步长、变量、真实值和预测值。
- 每次运行使用独立输出目录；拒绝覆盖已有结果，不依靠用户删除旧文件来重跑。
- 固定随机种子不等于不同设备、版本下逐位相同。第一轮单种子用于检查流程，论文结论仍需后续重复实验。

## 8. 验收标准

1. 先写失败测试再实现功能；合成测试数据必须明确标注，不能作为真实预测效果展示。
2. 手算小序列验证 X/y 切片；检查三集合目标时间互不交叉。
3. 验证/测试加入极端值后，训练集均值和标准差不改变。
4. 改变某预测起点后的实际值，不应改变该起点的历史输入或两个朴素基线输出。
5. 固定 24 小时基线在长于 24 小时的预测区间也不读取未来；常数列、缺小时、重复小时和不足历史有测试。
6. 用小型合成样本完成 MLP 前向、反向、优化、早停保存与重新加载；核对加载前后的预测和原单位指标。
7. 输入文件不被修改；已有输出目录拒绝覆盖；损失非有限时测试应失败。
8. 本地执行完整测试和 CLI 帮助检查，通过后提交推送，并核对本地和 GitHub 提交号相同。
9. 实际 ERCO 完整训练、显卡兼容性和真实误差以用户服务器后续运行结果为准，不以本地合成测试代替。
